## Description

CORE's own worked examples (§9.2, §11.2–§11.6, §3) used seven predicate names and one role
name that were never registered as `_schema/Property/` nodes in §10 as of CORE 0.10/0.11 — the
revision `arc init`'s seeded vocabulary was built against. Spec 023 knew about this ambiguity
(its own program brief, `CORE-FIX.md` §8.5, catalogued exactly these seven names) and made a
deliberate call: keep registering all seven, on the reasoning that a tool registering an
otherwise-undocumented predicate is "more conformant than the spec, not less." CORE 0.12
closes that ambiguity from the other side — by renaming or removing each of the seven — which
inverts spec 023's decision for six of them and leaves one (`relevance`) removed from prose
only. Every one of the seven predicates spec 023 chose to keep is present, verbatim, in the
current seeded vocabulary:

```
internal/app/schema/kernel/schema.go:90  "definition":  {Role: "text", Merge: MergeFirstWriteWin, ...}
internal/app/schema/kernel/schema.go:91  "notes":       {Role: "text", Merge: MergeAppend, ...}
internal/app/schema/kernel/schema.go:92  "ref":         {Role: "meta", Merge: MergeImmutable, ...}
internal/app/schema/kernel/schema.go:93  "year":        {Role: "meta", Merge: MergeImmutable, ...}
internal/app/schema/kernel/schema.go:94  "status":      {Role: "meta", Merge: MergeLastWriteWin, ...}
internal/app/schema/kernel/schema.go:95  "relevance":   {Role: "text", Merge: MergeFirstWriteWin, ...}
internal/app/schema/kernel/schema.go:96  "granularity": {Role: "meta", Merge: MergeImmutable, ...}
internal/app/schema/kernel/schema.go:85  "authors":     {Role: "meta", Merge: MergeUnion, ...}   (kept alongside "author")
```

Each is used verbatim in the current `CoreTypeDefs` Required/Optional lists (`Entity` requires
`definition`; `Resource`/`Entity` permit `notes`; `Reference` permits
`url, authors, year, doi, isCitedBy, ref, relevance, status, notes`; `Timeline` permits
`granularity, period, heading`). §16's own conformance checklist ("every predicate is camelCase
and registered as a `_schema/Property/` node") is not violated by the *tool* today — every one
of these is in fact registered — but the graph content it produces is not portable to another
CORE-0.12-conformant tool, because six of the eight names above no longer exist in §10 at all.

## Root Cause Analysis

This is not an implementation defect against the spec version the tool was built for — `go test ./...` conformance tests for spec 023 pass, and every predicate the original report flags is genuinely registered, matching spec 023's Assumptions verbatim. The root cause is that the upstream spec itself moved: CORE 0.10/0.11 left seven predicate names ambiguous (used in worked examples, never formally registered), spec 023 made a documented, reasoned choice to resolve that ambiguity by keeping and registering all seven, and filed the ambiguity upstream (`CORE-FIX.md` §8.5) rather than guessing wrong. CORE 0.12 has now resolved the same ambiguity from the spec side, in the opposite direction for six of the eight names — a **spec conflict with an already-shipped, deliberate implementation decision**, not implementation drift. The one piece of genuinely new scope this report surfaces beyond a straight schema-table edit is `internal/core/markdown.go`'s `textPredicateFor`, which encodes `"definition"` and `"notes"` as literal round-trip keys outside the schema tables entirely.
